# Presentation directions

Five initial devices: a query travelling into its source; a researcher collecting
occurrences; a field guide to notation; an extraction pipeline; a split-screen
paper and search session.

## Selected: follow the notation

The notation is the thread: start with the original equation, watch a real query
return two occurrences, narrow to page 2, and save the occurrence. A wide workspace
gives way to readable crops, then returns to the actual excerpt. This makes the
product's purpose visible before introducing its implementation.

First two seconds: the squared weight from the original PDF and the sentence
"One notation. More than one place." The product capture arrives through that
same query. Original screens remain unaltered; framing and titles are editorial.

Beats: original equation -> live search -> page filter -> bookmark -> original
excerpt -> local workflow and project name. Ground #eef4f2, ink #142d29, teal
#086f64, Inter 400/700. Silent by design for a GitHub README and muted playback;
all necessary explanation is visible. No voiceover or stock music is required.

## Alternative: a reader's field guide

A book-like sequence explains Contains, Exact, and scalar algebra with mathematical
examples and side-by-side evidence. The first two seconds compare a fraction and
its numerator. It would be useful as a tutorial, but spends longer explaining
matching contracts before showing the workflow.

## Alternative: inside the search engine

A diagram follows a paper through TeX/PDF extraction into the notation index and
back to an occurrence. The first two seconds split a page into source and glyph
paths. This would suit an architecture explainer; it is less direct for a visitor
deciding whether to install the extension.
